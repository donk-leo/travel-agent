# 实验项目 7：程序性知识应用——旅游规划 Agent

## 一、目标与输入

使用项目 6 已构建的景区知识图谱，结合本地大语言模型和有限轮次工具调用，实现旅游需求解析、图谱查询、路线建议及来源追溯。输入为 `v0.6-p06` 的 `graph_nodes.csv` 与 `graph_edges.csv`；本实验只读图谱，不读取原始游记。输入文件与该标签的对应文件一致。

## 二、方法与实现

- **交互及配置**：Flask 网页接收用户输入；Ollama 本地 `qwen3:8b` 通过 `/api/chat` 提供模型推理。模型和地址由 `P07_OLLAMA_MODEL`、`P07_OLLAMA_URL` 可选环境变量配置，默认使用本地服务。
- **需求解析与追问**：解析景区、天数、同行人群、偏好和限制。缺少规划所需信息时追问，网页通过会话暂存原需求。模型检查明显矛盾，出错或信息不足时提示，不把空结果伪装成路线。
- **工具调用与编排**：`agent.py` 根据需求让模型选择图谱工具，调用后将真实结果摘要反馈给模型，再决定结束或补查，最多 3 轮。工具由白名单限制；每次调用记录实际参数和返回值。`get_route_candidates` 以来源文档分组展示 `NEXT` 候选；`search_poi` 按景区列出或按关键词查找；`get_conditions` 读取条件建议；`neighbors` 提供节点出边查询。
- **路线生成与核验**：模型从候选连接提出节点序列；程序逐段检查有向 `NEXT`，缺少直接边时尝试通过图谱中的有向路径插入中间节点，再次逐段核验。合理往返可保留，重复节点会提示；缺失实际距离、坡度、时长和适用性时应进一步确认。
- **结果及证据**：网页展示需求、决策摘要、路线、建议和来源，可展开工具记录。新版 JSONL 保存输入、解析、决策摘要、工具调用与观察、最终结果。决策摘要不是模型内部思维链。历史记录可能为旧格式。

配置、依赖、运行和一条命令重跑案例见本项目 [README](../README.md)；接口定义见仓库 `standards/schema_tools.json` v1.2。v1.2 明确现有的按来源分组查询工具，并将返回字段写成结构化 Schema；P6 图谱未修改。上线或多人共享前需对接口变更进行组内复核。

## 三、测试结果

本次使用真实本地 `qwen3:8b` 运行 8 条人工设计的测试输入，覆盖亲子老人一日、朋友白云山、伴侣武功山两日、信息不足、合并追问、冲突要求、虚构名称无匹配、景点列表；详见 [测试记录](../outputs/tests.md)、[原始结果](../outputs/evaluation_results.json) 和各案例 JSONL 轨迹。

- 真实运行中，亲子老人、朋友白云山和武功山两日请求均得到了通过 `NEXT` 连接核验的路线；这不等于实际道路可走或满足时间、体力和预算。
- 信息不足、冲突案例返回补充问题；虚构地点查询返回图谱无匹配提示；白云山列表返回图谱中的 42 条 POI 记录。此数量可从原始结果复核，不代表官方景点总数。
- 配套离线单元测试对图谱查询、空结果补查、上下文衔接、冲突拦截、轮次上限和无匹配处理进行检查。测试中的模型响应使用模拟值，不能代替上述真实模型测试。
- [完整示范](../outputs/demo.md) 展示一条亲子老人请求的约束解析、决策、路线及逐段来源。

## 四、失败现象、原因和后续方案

1. **理由串到其他建议**：早期模型返回某个编号，同时写了另一条建议的理由。现改为先按编号取回原建议，再针对单条建议生成理由；本次仍观察到“减少步行”等缺少实际距离证据的推测。后续可对理由的事实依据及条件进行标注和人工评测，不把模型推测当作图谱事实。
2. **模型编造直接连接**：白云山路线两处缺少 `NEXT` 边，重试仍未修复。现由程序查找图谱间接路径并逐段核验；补全可能导致重复路段，不能从节点重复数推导实际距离。后续可与组员研究整体路线优化及有距离数据的评估。
3. **无匹配前误判**：曾对陌生景点名在查图谱前声称不存在。现将没有额外限制的普通信息查询交给图谱，未命中时说明“图谱中未找到”，不声称现实中不存在。模型对其他场景仍可能误判。
4. **范围和需求表达**：图谱使用“广州白云山”，简称“白云山”及“长隆欢乐世界”等子园区范围仍需处理；“朋友”在本次测试中未进入人群字段。后续可研究实体名称解析及明确子园区归属，避免静默扩大范围。
5. **多日安排与实时信息**：武功山两日请求未产生逐日安排；票价、气候、日出时间、步行强度与开放状态不完整。后续需增加有来源的数据和用户约束评估，信息缺失时继续说明。
6. **规划需求漏选路线工具**：网页体验中模型将白云山一日游识别为规划，却只选择建议和地点查询。现对规划请求补充路线查询，并将系统补充与模型选择分别记录；离线回归覆盖该分支，真实模型隔离网页测试也展示了经图谱核验的路线。
