# 项目 7：旅游规划 Agent

项目 7 读取项目 6 的图谱，结合本地 Ollama 模型，提供旅游需求理解、图谱查询、路线建议及来源展示。原交付版本为 `v0.7-p07`；2026-11-09 针对审核意见完成两项优化后合并，版本为 `v0.7.1-p07`。

2026-11-09 针对审核意见做了两项优化（待复核）：

- **子园区范围**：用户说“长隆欢乐世界”时，景区名仍归一为“长隆”，但后续路线与景点查询会优先限制在该子园区，并说明当前范围；连接不足时才回退整个景区。
- **重复绕行**：图谱核验通过后，按 NEXT 连接对目标地点重新排序（保留起点和明确返程终点），减少同一批景点被反复经过；同时输出“步数 / 重复次数”结构指标。图谱没有距离和坡度字段，因此指标不能换算成实际体力消耗。

2026-11-09 本地修改（尚未提交）：多日请求把 `duration_days` 传入路线规划，要求模型返回按天分组的 `day_plan`；页面按天展示；模型未给出或分组不合法时按节点数均分，并写入不确定性说明。人群/体验偏好词（儿童、亲子、老人、情侣、刺激、少走路等）不再当成地点名称搜索，改为列出当前范围全部地点，并在页面标注“未按偏好过滤”。

## 环境

- Python 3.9 或以上；本次实际环境：Python 3.9.6、Flask 3.1.3。
- Ollama 服务可用，并已下载 `qwen3:8b`：

```bash
ollama pull qwen3:8b
python3 -m pip install -r analysis/p07_agent/requirements.txt
```

启动前请确保 Ollama 服务正在运行。默认地址为 `http://localhost:11434/api/chat`，默认模型为 `qwen3:8b`。使用本地 Ollama 不需要 OpenAI API 密钥。

可选的环境变量见 `.env.example`。例如，在启动程序的终端中执行：

```bash
export P07_OLLAMA_URL=http://localhost:11434/api/chat
export P07_OLLAMA_MODEL=qwen3:8b
```

程序读取进程环境变量，不会自动加载 `.env` 文件；不配置时使用上述默认值。

## 启动网页

在仓库根目录执行：

```bash
python3 analysis/p07_agent/src/web_app.py
```

打开终端显示的本地地址，输入需求，例如“我想带孩子和老人去长隆玩一天，喜欢游乐项目，尽量少走路”。规划需求缺少景区或天数时会追问；可以点击“开始新需求”清除当前追问上下文。网页可展开查看决策摘要、图谱来源和工具调用记录。

## 重跑检查和案例

在仓库根目录执行：

```bash
python3 -m unittest discover -s analysis/p07_agent/tests -v
python3 analysis/p07_agent/src/run_evaluation.py
python3 analysis/p07_agent/src/analyze_route_optimization.py
python3 checks/check_agent.py analysis/p07_agent/
```

第一条是离线流程测试，使用模拟模型和真实图谱，覆盖别名归一、子园区识别与筛选、路线补全与重排、追问上下文、冲突拦截等；第二条实际调用本地模型，覆盖亲子、老人、朋友、伴侣、信息不足、冲突、无匹配及地点列表，可能需要数分钟。它会生成 `outputs/evaluation_results.json` 和新的 `outputs/sessions/*.jsonl`。这些案例是人工编写的测试输入，不是原始游记数据。第三条把已有真实模型路线离线交给整理算法，输出前后对照表，不调用模型。第四条检查约定的交付文件。

评估脚本是一条命令重跑案例，不等于保证语言模型逐字输出一致；模型版本、推理环境及图谱版本可能影响结果。`outputs/tests.md` 和 `outputs/demo.md` 记录了本次运行与人工分析，不会在每次重跑后自动重写。

## 流程和输入

`src/agent.py` 是主流程：需求解析 → 决定追问/回复/查图谱 → 需求检查 → 模型选择工具 → 读取工具结果并决定是否补查（最多 3 轮）→ 方案检查 → 返回结果及会话记录。行程规划需要路线证据；如果模型漏选路线查询，系统会补充调用并单独记录。

- 图谱只读：`analysis/p06_graph/outputs/graph_nodes.csv`、`graph_edges.csv`，来源标签 `v0.6-p06`。
- `tools.py` 提供 `search_poi`、`get_route`、`get_conditions`、`neighbors` 及按来源分组的 `get_route_candidates`；另有内部函数 `route_metrics`（结构指标）、`optimize_route`（路线整理）、`repair_route`（补全断开的连接）。
- `route_planner.py` 根据候选图谱连接规划，使用 `validate_route` 检查方向；直接连接缺失时可搜索间接 `NEXT` 路径。核验通过后调用 `optimize_route` 整理顺序，具体规则见下。
- `constraint_checker.py` 在规划前和最终方案输出前进行模型检查；模型会误判，检查不能保证覆盖全部限制。
- `trace_log.py` 保存 JSONL。新版记录包含用户输入、意图、决策摘要、子园区筛选、路线整理、工具参数及观察、最终结果；旧版记录可能只含工具调用。会话记录会包含请求文字，分享前应检查内容。

子园区范围由 `src/sub_area_scope.py` 处理：

- 文档级园区标签取自 P1 已入库 CSV 的 `doc_id` / `subtype`（8 条长隆文档，测试会与 P1 对照）；
- 景点级归属用 P6 节点自带的 `source_doc_ids` 叠加文档标签，出处跨园区或只有综述文档时记为“未知”，不猜测；
- `scope.sub_area` 会写进路线规划请求，`get_route_candidates` 的候选只保留该园区来源；连接不足时回退整个景区并在结果中说明；
- `search_poi` 的结果也会按园区筛选，园区内为空时回退并提示。

`src/route_planner.py` 在逐段核验通过后调用 `tools.optimize_route`：

- 保留模型给出的起点；如果终点是之前走过的地点（通常表示返程），也保留为终点；
- 其余目标地点用 Held-Karp（≤14 个）或贪心最近邻重排，使总 NEXT 步数最少；
- 只有结构成本（步数 + 2×重复次数）下降、且重排后的路线仍逐段通过核验时才采用，否则保留原路线；
- 结果里的 `metrics` 记录步数、重复次数、缺失路段；`uncertainties` 会说明这是图谱步数而非实际距离。

规划请求的 POI 关键词没有名称匹配时，系统会改为列出该景区（或该子园区）全部 POI，并在页面提示“没有名称匹配”；但这只是把已有图谱地点摊开，不代表用户偏好一定有对应标签。人群/体验偏好词（儿童、亲子、老人、情侣、刺激、少走路等）会直接走“当前范围全部地点”，不再当地点名搜索，页面标题为“当前范围地点”，并注明列表未按偏好过滤。路线存在但图谱连接核验不通过时，状态为 `partial`（不是 `complete`），保留路线供参考并提示调整需求或改用官方路线。离线复算整理效果可运行 `python3 analysis/p07_agent/src/analyze_route_optimization.py`。

工具接口见 `standards/schema_tools.json`。v1.2 在此前确认的 `get_route` 来源字段基础上，明确补充现有的 `get_route_candidates` 分组接口；未更改 P6 图谱。

## 已知限制

- `NEXT` 表示来源资料中的步骤顺序，并非现场道路网络；图谱没有实际距离、坡度和通行情况，路线整理只能减少重复经过和 NEXT 步数，不能据此保证少走路或某天能完成。
- 子园区范围目前只覆盖长隆，依赖 P1 文档标签与 P6 的 `source_doc_ids`；出入口、`熊猫村` 等跨园区或只出现在综述文档里的地点记为“未知”，不强行归属。飞鸟乐园在 P2/P3 中没有节点，会回退整个景区并提示。
- 子园区筛选会排除多园区总览路线（`CL-O-01`），因此园区内可用路线可能更少；水上乐园在现有图谱里没有可用的 NEXT 连接，仍会回退整个景区。
- 路线整理会改变模型给出的游览顺序（保留起点和返程终点），可能与模型的时段安排不一致；时段、开放状态和适龄性仍缺少数据。
- 多日请求会把 `duration_days` 传给路线规划，页面按 `day_plan` 分天展示；模型未给出或分组不合法时按节点数均分并标注不确定性。分天只是展示分组，不代表每日步行强度、住宿点或开放时间已经合理；预算、日出时间、适龄性和活动开放情况仍缺少完整数据，模型推测及历史来源信息不能当作实时核实。
- 有时会漏掉“朋友”等人群；景区简称已做归一，但组合路线中的重复路段只能按图谱结构优化，无法用真实距离评估。
- 图谱地点列表基于既有抽取，可能包含车站、餐厅、噪声或遗漏，不是官方完整景点名录。
- 模型工具选择、理由生成和冲突检查可能误判；无匹配只说明图谱中没有查到，不能断言现实中不存在。

当前实验记录、示范及报告分别见 `outputs/tests.md`、`outputs/demo.md`、`report/p07_experiment_report.md`。审核结论及 reviewer 字段的说明见 `standards/handover/p07_agent.yaml`。
