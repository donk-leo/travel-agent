**文件约定**

- 路径：`scenic/<area>/data/processed/<area>_guides.csv`
- 编码：**UTF-8-SIG**（Excel 直接打开不乱码）
- **`raw_content` 口径（三景区必须一致）**：抽取后的**纯文本**，不含 HTML 标签与实体，但**保留**页面模板噪声（作者行、发布日期、页脚导航等）。因此 `char_raw` 是纯文本长度、跨景区可比较；删标签属于“抽取”而非“清洗”，不计入 `removed_char_ratio`。
- 格式：逗号分隔、含表头；`raw_content` / `clean_content` 内允许换行
- `<area>` 取值：`changlong` / `baiyunshan` / `wugongshan`

## 2. `doc_id` 编码

格式：`<景区码>-<O|T>-<两位序号>`

| 景区 | 景区码 | 官方路线 | 游客游记/站点攻略 |
|---|---|---|---|
| 长隆旅游度假区 | `CL` | `CL-O-01` | `CL-T-01` |
| 广州白云山 | `BYS` | `BYS-O-01` | `BYS-T-01` |
| 萍乡武功山 | `WGS` | `WGS-O-01` | `WGS-T-01` |

规则：

1. 编号**只增不减、删了不回收**（避免下游按 ID 引用时错位）；
2. 打 tag 后 `doc_id` **冻结**，不得重排；
3. 新增文档追加在末尾，不要插入到中间。

## 3. `doc_type` 取值与验收口径

| 值 | 含义 | 纳入标准 |
|---|---|---|
| `官方路线` | 官方发布的**推荐游览路线** | 页面必须是路线/行程内容（"一日游""推荐线路""A/B/C 线"）；**不接受**入园须知、门票页、景点介绍首页、新闻公告 |
| `游客游记` | 真实个人发布的游玩记录 | 有作者、有具体时间地点与顺序；**不接受**站点编辑的 SEO 汇总页 |
| `站点攻略` | 平台编辑/SEO 生成的攻略页 | 可用，但必须单独标注，**不得冒充个人游记** |

**每景区最低要求**：`官方路线` ≥ 1 条 + 有效 `游客游记` ≥ 3 篇（任务书口径，建议各 5 篇）。
`is_valid=False` 的条目保留，但要写 `quality_flags` 说明原因。

> 历史遗留：`archive/legacy_collect_2026-10-28/采集结果.csv` 中 `类型` 列用了
> `游客攻略（去哪儿）`、`官方资料`，**不属于上述合法值**，因此该文件不参与合并；
> 如需复用，必须先经 `scenic/changlong/src/import_legacy.py` 转换并重标类型。

## 4. 命名与编码

| 类别 | 规则 | 例 |
|---|---|---|
| 目录 | 小写 ASCII + `_` | `scenic/wugongshan/`、`analysis/p02_entities/` |
| Python 脚本 | snake_case，动词开头 | `collect_pages.py`、`parse_routes.py` |
| 项目输出 | 固定文件名（见 handover 卡） | `entities.jsonl` |
| 文档 | `NN_中文名.md` | `03_交接标准.md` |
| 分支 | `<成员>-<任务>` | `happiness-p03-routes` |

- 代码文件统一 **UTF-8（无 BOM）**，换行 LF；
- 数据 CSV 统一 **UTF-8-SIG**；
- 禁止在路径中使用空格与中文标点（中文目录名在迁移时已改为 ASCII）。

## 6. 冻结与版本

打 tag 之后以下内容**冻结**，改动必须升 tag 并通知全组：

1. `doc_id` 分配；
2. `clean_content`（一旦被下游引用，重跑会导致位置漂移）；
3. 各项目的枚举值（实体类型、`doc_type`、条件类型、节点/边类型）；
4. span 口径（`clean_content` 为准、0 起、不含结尾）。

建议 tag 序列：`v0.1-p01` → `v0.2-p02` → … → `v0.8-final`。

## 8. 跨景区汇总层（`scenic/summary/`）

三景区数据冻结后，由 `scenic/summary/src/build_summary.py` 合并为一份跨景区数据层：

```
scenic/summary/
├─ data/三景区汇总数据集.csv    # 29 条 × 24 列，按 clean_hash 去重
├─ data/三景区汇总统计.csv      # 按景区 × 类型统计
├─ outputs/                     # 质检 Markdown、清洗前后对比、统计摘要、Excel（7 表）
├─ report/                      # 项目1 小组报告 docx/pdf + 3 张图
└─ src/                         # build_summary / qc_summary / make_summary_figures / build_report
```

规则：

1. **只读**三个景区的 `*_guides.csv`，不重新清洗、不修改 `clean_content`；
2. 任一景区数据变化（升 tag）后必须**重跑整条汇总流水线**，否则汇总表与报告数字会过期：
   ```powershell
   python scenic/summary/src/build_summary.py
   python scenic/summary/src/qc_summary.py
   python scenic/summary/src/make_summary_figures.py
   python scenic/summary/src/build_summary_report.py
   # 再用 LibreOffice 把 docx 导出为 pdf
   ```
3. 汇总层由 T0coke 维护；其他人发现数据变化时提醒他重跑。
4. **汇总产物自带“生成时间”**（`三景区质量检查.md` 的生成时间行、xlsx 的文档属性），
   因此重跑后 `git status` 会出现这两处差异，属正常、不是数据变化。
   提交前用 `git checkout -- scenic/summary/outputs/` 还原即可，或随本次提交一起带上。
5. 换行符统一为 **LF**（`.gitattributes` 已固定），CSV 写出显式用 `lineterminator="\n"`；
   若新增脚本写 CSV，请沿用这两条，否则重跑会产生“假修改”。
