# 三人协作统一规范（项目 1）

> 目标：**三个人各自做的景区数据，能一条命令合并成「三景区汇总数据集」**，并且格式、字段、口径完全一致。
> 本规范以 `武功山/data/processed/wugongshan_guides.csv` 的实际表结构为准（该表已实现，合并脚本 `武功山/src/merge_group.py` 也按它校验）。
> 有任何分歧，以本文件为准；改本文件请先在群里说一声。

---

## 1. 目录约定：一人一个景区目录，互不覆盖

```
仓库根/
├─ README.md                 ← 组内总览（组长维护）
├─ docs/                     ← 协作规范（全员只读，改动先商量）
│  ├─ 统一规范.md            ← 本文件
│  └─ 协作流程.md            ← Git 操作与分工
├─ scripts/
│  └─ check_dataset.py       ← 交付前自检（列是否齐、能否合并）
├─ 长隆/                     ← 长隆旅游度假区（负责人：本人）
├─ 白云山/                   ← 广州白云山（负责人：待填）
└─ 武功山/                   ← 萍乡武功山（负责人：T0coke，已完成）
```

- **一个顶层目录 = 一个人**，目录内随便怎么组织，别人不进来改；
- 公共文件（根 README、docs、scripts）改动前在群里说一句；
- 每个景区目录内部沿用武功山的结构，方便互相抄：

```
<景区>/
├─ config/sources.csv        采集清单（doc_id/类型/标题/作者/日期/站点/URL）
├─ data/raw/                 原始快照 + manifest.csv（URL、字节、时间、SHA256）
├─ data/interim/             正文抽取结果（未清洗）
├─ data/processed/<area>_guides.csv   ★主数据集（交付物）
├─ src/                      采集、抽取、清洗、构建、合并
├─ outputs/                  质量检查报告、清洗前后对比、统计摘要
├─ report/                   实验报告 docx/pdf + 图
├─ requirements.txt
└─ README.md
```

**交付物的唯一文件名约定**：`data/processed/<area>_guides.csv`
（`<area>` 用小写英文/拼音：`changlong`、`baiyunshan`、`wugongshan`）

## 2. 主数据集字段（24 列，与武功山完全一致）

前 9 列是**合并必需**，缺任何一列 `merge_group.py` 会直接报错退出。

| # | 字段 | 必填 | 类型 | 含义 |
|---|---|---|---|---|
| 1 | `doc_id` | ✅ | str | 唯一编号，见第 3 节 |
| 2 | `scenic_area` | ✅ | str | 景区名（长隆 / 广州白云山 / 武功山） |
| 3 | `doc_type` | ✅ | str | 官方路线 / 游客游记（见第 4 节） |
| 4 | `subtype` | | str | 细分：一日游 / 两日游 / 亲子 / 夜爬 … |
| 5 | `title` | ✅ | str | 标题 |
| 6 | `author` | | str | 作者；缺失写 `未知` |
| 7 | `publish_date` | | str | `YYYY-MM-DD`；缺失写 `未知` |
| 8 | `source_site` | ✅ | str | 站点名（长隆官网 / Trip.com / 小红书 …） |
| 9 | `source_url` | ✅ | str | 原始链接（唯一回溯入口） |
| 10 | `extract_rule` | | str | 正文定位规则（如 `官网-div.flow-list`） |
| 11 | `raw_content` | ✅ | text | 抽取后、清洗前的正文（保留噪声，供复核） |
| 12 | `clean_content` | ✅ | text | 清洗后正文 ★后续项目只读这一列 |
| 13 | `char_raw` | | int | 去空白字符数（清洗前） |
| 14 | `char_clean` | | int | 去空白字符数（清洗后） |
| 15 | `para_raw` | | int | 段落数（清洗前） |
| 16 | `para_clean` | | int | 段落数（清洗后） |
| 17 | `removed_char_ratio` | | float | 删除比例 |
| 18 | `noise_lines_removed` | | int | 删除的噪声行数 |
| 19 | `emoji_removed` | | int | 删除的 emoji 数 |
| 20 | `urls_removed` | | int | 删除的链接数 |
| 21 | `dup_paragraphs_removed` | | int | 删除的重复段落数 |
| 22 | `quality_flags` | | str | 分号分隔的标记，如 `作者缺失;文本过短` |
| 23 | `is_valid` | ✅ | bool | `True`/`False`，是否达到最低字数与信息量 |
| 24 | `clean_hash` | | str | `sha1(去掉空白后的 clean_content)`，合并去重用 |

编码：**UTF-8-SIG**（Excel 直接打开不乱码），CSV 逗号分隔、含表头、`clean_content` 内允许换行。

## 3. `doc_id` 编码

格式：`<景区码>-<O|T>-<两位序号>`

| 景区 | 景区码 | 官方路线 | 游客游记 |
|---|---|---|---|
| 长隆旅游度假区 | `CL` | `CL-O-01` | `CL-T-01` |
| 广州白云山 | `BYS` | `BYS-O-01` | `BYS-T-01` |
| 萍乡武功山 | `WGS` | `WGS-O-01` | `WGS-T-01` |

规则：编号一旦分配**不再复用**（删掉的条目编号作废），避免后续项目按 ID 引用时错位。

---

## 4. `doc_type` 取值与验收口径

只允许三个值：

| 值 | 含义 | 纳入标准 |
|---|---|---|
| `官方路线` | 官方发布的**推荐游览路线** | 页面必须是路线/行程内容（“一日游”“推荐线路”），**不接受**入园须知、门票页、景点介绍首页、新闻公告 |
| `游客游记` | 真实个人发布的游玩记录 | 有作者、有具体时间地点与顺序；**不接受**站点编辑写的 SEO 汇总页 |
| `站点攻略` | 平台编辑/SEO 生成的攻略页 | 可用，但必须单独标注，不得冒充个人游记 |

**每景区最低要求**：`官方路线` ≥ 1 条 + 有效 `游客游记` ≥ 3 篇（任务书口径；建议各 5 篇）。

> 注意：目前"采集.py"里的去哪儿页面属于 `站点攻略`，不是个人游记；武功山那份 8 篇游记里 1 篇为图片帖，已标 `is_valid=False`。

## 5. 长隆数据的字段映射（本人原有数据的转换规则）

我本地已按另一套英文表结构做好了长隆数据集，交付时按下表转换，**不另立标准**：

| 标准字段 | 我的原字段 | 转换规则 |
|---|---|---|
| `doc_id` | `doc_id` | `CHL-O01` → `CL-O-01`（补零、改分隔符） |
| `scenic_area` | `scenic_area` | 统一写 `长隆` |
| `doc_type` | `doc_type` | 官方路线 / 游客游记（不变） |
| `subtype` | — | 由 `park` + 行程天数补充，如 `野生动物世界-一日游` |
| `title` | `title` | 原样 |
| `author` | `author` | 原样；空则 `未知` |
| `publish_date` | `publish_date` | 空则 `未知` |
| `source_site` | `source_site` | 原样 |
| `source_url` | `source_url` | 原样 |
| `extract_rule` | `extract_rule` | 原样 |
| `raw_content` | `raw_text` | 原样 |
| `clean_content` | `clean_text` | 原样 |
| `char_raw` | `char_count_no_space` 的清洗前版本 | 用 `len(re.sub(r"\s+","",raw))` 重算 |
| `char_clean` | `char_count_no_space` | 直接对应 |
| `para_raw` / `para_clean` | — | 按换行切分非空行计数 |
| `removed_char_ratio` | `reduction_rate` | 同名换义，注意是"删除比例" |
| `noise_lines_removed` 等 | `cleaning_log` | 由清洗日志解析出各项计数 |
| `quality_flags` | — | 由 `is_valid`、缺失字段、子园区生成 |
| `is_valid` | `is_valid` | 布尔值统一写 `True`/`False` |
| `clean_hash` | — | `sha1(去空白 clean_content)` |

转换脚本放在 `长隆/src/export_standard.py`，转换后跑 `python scripts/check_dataset.py 长隆/data/processed/changlong_guides.csv` 自检。

## 6. 交付前自检（必做）

```powershell
python scripts/check_dataset.py 长隆/data/processed/changlong_guides.csv
```

检查内容：列是否齐全、`doc_id` 格式、`doc_type` 取值、`is_valid` 可解析、`clean_content` 非空、
`clean_hash` 是否重复、每景区"官方路线 ≥1 且有效游记 ≥3"是否满足。
最后一行会告诉你**能不能直接合并**。

三人全部自检通过后，在 `武功山/` 下跑：

```powershell
cd 武功山
python src/merge_group.py ..\长隆\data\processed\changlong_guides.csv `
                          ..\白云山\data\processed\baiyunshan_guides.csv `
                          data\processed\wugongshan_guides.csv
```

## 7. 质量与合规底线

1. **数字必须可复算**：报告里的统计量来自脚本输出，不手写；
2. **原始页面可追溯**：`source_url` + `data/raw/manifest.csv`（含 SHA256）；
3. **不伪造数据**：需登录态才能抓的数据（如小红书）要标注"需登录态，仅本人可复现"；
4. **礼貌采集**：请求间隔 ≥2 秒，先读 robots.txt，不绕验证码；
5. **版权**：数据仅用于课程实验，引用标注来源；不二次分发全文。
