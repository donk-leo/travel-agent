# 三人协作流程（Git 操作手册）

> 给第一次用 GitHub 协作的成员。照着做就不会把别人的代码覆盖掉。
> 核心只有一句：**改之前先拉，改完只交自己的目录。**

---

## 1. 第一次接手（每人只做一次，约 10 分钟）

1. 组长在仓库页 `Settings → Collaborators` 邀请你 → 你去邮箱/GitHub 通知里点 **Accept**；
2. 装 Git（`git --version` 能出版本号即可）；
3. 拉到本地并配置身份：

```powershell
cd C:\Users\你的用户名\Desktop\学校\数据挖掘
git clone https://github.com/donk-leo/-.git 团队仓库
cd 团队仓库
git config user.name  "你的名字"
git config user.email "你的GitHub邮箱"
```

> 身份只用这一次，之后所有提交都会显示成你。**务必用自己的邮箱**，否则分工记录会算到别人头上。

4. 确认环境能跑：

```powershell
python scripts/check_dataset.py 武功山/data/processed/wugongshan_guides.csv
```

应当输出 `通过`，说明 Python 与数据都正常。

## 2. 每天干活的循环（90% 的时间都在重复这 5 步）

```powershell
git pull                      # ① 先同步，别跳过
# ② 改自己目录里的文件（长隆/ 之类）
git status                    # ③ 看自己动了哪些文件
git add 长隆/                  # ④ 只加自己的目录，别 git add -A
git commit -m "长隆: 完成实验二实体识别"
git push                      # ⑤ 上传
```

**commit message 格式**：`景区: 动作`
例：`长隆: 补官方路线 3 条`、`武功山: 修正清洗规则 R6`、`公共: 更新字段规范`

提交信息会永久留在历史里，既是复习线索，也是分工证据。

## 3. 推荐流程：开分支 + PR（比直接推 main 安全）

直接推 `main` 出错会污染所有人。稳妥做法：

```powershell
git pull
git checkout -b changlong-lab2       # 建自己的分支（名字随意但别重复）
# …改文件…
git add 长隆/
git commit -m "长隆: 实验二实体识别"
git push -u origin changlong-lab2    # 推分支
```

然后浏览器打开仓库 → 会看到黄色提示条 **Compare & pull request** → 点它 → 写一句话 → `Create pull request`
→ 组员点 `Approve` → `Merge pull request`。

好处：`main` 永远是能跑的版本；出问题删分支就行，不动主线。

## 4. 冲突了怎么办

`git pull` 或 `git push` 时若提示 `CONFLICT`，打开冲突文件会看到：

```
<<<<<<< HEAD
你本地的写法
=======
云端/别人的写法
>>>>>>> origin/main
```

处理：**手动改成你想要的样子，把三行标记全删掉**，然后

```powershell
git add 冲突的文件
git commit -m "merge: 解决冲突"
git push
```

不确定就先备份文件再动手，**不要**用 `git push -f` 硬推（会覆盖别人提交，且难以找回）。

## 5. 文件归属（谁可以改什么）

| 路径 | 谁能改 |
|---|---|
| `长隆/` | 只有长隆负责人 |
| `白云山/` | 只有白云山负责人 |
| `武功山/` | 只有 T0coke |
| `docs/`、`scripts/`、根 `.gitignore` | 改动前在群里说一声（谁提谁改） |
| 根 `README.md` | 组长维护，其他人只在"目录/进度"表里更新自己那一行 |

**报告 docx/pdf**：二进制文件无法自动合并，**同一份 docx 只能一个人改**。
每位成员只交自己景区的报告（放 `<景区>/report/`），总报告由组长最后拼装。

## 6. 明确禁止

1. `git push -f`（强推覆盖别人提交）；
2. 提交 `.env`、密钥、cookie、登录态文件、`storage_state.json`；
3. 提交 `__pycache__/`、虚拟环境、`.dsh-office-*` 预览目录；
4. 提交单文件 > 50MB 的数据（先压缩或改存 manifest + 采集脚本）；
5. 直接修改别人目录里的文件（要改先在群里说，由负责人改）；
6. 把 `data/raw/html/*.html` 全量提交（体积大，`.gitignore` 已忽略，用 manifest.csv 记录 SHA256 即可）。

## 7. 常见坑速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `push` 被拒（rejected） | 云端有你没有的提交 | 先 `git pull`，解决冲突后再 push |
| `fatal: not a git repository` | 不在仓库目录里 | `cd` 到 `团队仓库` 目录 |
| 提交显示成别人的名字 | 没配 `user.name/email` | `git config user.name/email` 重设，之后的新提交才生效 |
| 中文文件名字乱码 | 控制台编码 | PowerShell 里 `chcp 65001`，或直接用资源管理器看 |
| Excel 打开 CSV 乱码 | 编码不对 | 数据集统一 UTF-8-SIG（本仓库已约定） |
| `git add .` 带进了一堆垃圾 | 图省事 | `git reset` 撤销暂存，改用 `git add 具体目录` |
| 大文件推送失败 | 超过 100MB | `git rm --cached` 该文件后加进 `.gitignore` |
