# 02 · 协作流程（Git 操作手册）

> 给第一次用 GitHub 协作的成员。照着做就不会覆盖别人的东西。
> 一句话：**改之前先拉，改完只交自己的目录，交付要打 tag。**
> 文件归属见 `AGENTS.md` 第 4 节；项目契约见 `03_交接标准.md`。

---

## 1. 第一次接手（每人一次，约 10 分钟）

1. 组长在仓库页 `Settings → Collaborators` 邀请你 → 点邮件里的 **Accept**；
2. 装 Git（`git --version` 有版本号即可）；
3. 拉仓库并配置身份：

```powershell
cd C:\Users\你的用户名\Desktop\学校\数据挖掘
git clone https://github.com/donk-leo/travel-agent.git 团队仓库
cd 团队仓库
git config user.name  "你的名字"
git config user.email "你的GitHub邮箱"
python -m pip install -r requirements.txt
```

4. 验证环境：

```powershell
python checks/check_scenic.py scenic/wugongshan/data/processed/wugongshan_guides.csv
```

应输出 `通过`。

> 身份只配一次（本仓库内有效）。**必须用自己的邮箱**，否则提交记录会算到别人头上。

## 2. 日常循环（90% 的时间）

```powershell
git pull                                   # ① 先同步
# ② 改自己目录：scenic/<你的景区>/ 或 analysis/<你的项目>/
git status                                 # ③ 看动了哪些文件
git add scenic/changlong/                  # ④ 只加自己路径，别 git add -A
git commit -m "长隆: 转换 24 列并入库"
git push                                   # ⑤ 上传
```

commit 格式：`<范围>: <动作>`，例：`长隆: 补官方路线 3 条`、`公共: 新增实体 schema`。

## 3. 分支 + PR（推荐，尤其动公共层时）

```powershell
git pull
git checkout -b happiness-p03-routes      # <成员>-<任务>
# …改文件…
git add analysis/p03_routes/
git commit -m "P3: 路线解析初版"
git push -u origin happiness-p03-routes
```

浏览器打开仓库 → 会出现 **Compare & pull request** → 写说明（模板已内置）→ `Create pull request`
→ 组员 `Approve` → `Merge`。

**必须走 PR 的情况**：改 `lib/`、`checks/`、`standards/`、`docs/`、`README.md`、`AGENTS.md`。

## 4. 冲突处理

`git pull` 或 `push` 时提示 `CONFLICT`，打开文件会看到：

```
<<<<<<< HEAD
你本地的写法
=======
别人的写法
>>>>>>> origin/main
```

处理：手动合成为想要的样子，**删掉三行标记**，然后：

```powershell
git add 冲突的文件
git commit -m "merge: 解决冲突"
git push
```

不确定就先备份再改。**永远不要 `git push -f`。**

## 5. 交付（与 03 交接标准配套）

```powershell
git pull
python checks/check_pNN_xxx.py         # 必须退出码 0
# 更新 standards/handover/pNN_*.yaml：status: done、version_tag、reviewer
git add 你负责的路径
git commit -m "P2: 实体识别交付"
git tag -a v0.2-p02 -m "P2 交付：entities.jsonl + 规范表 + 词频图"
git push
git push origin v0.2-p02
```

tag 之后，`doc_id` / `clean_content` / 枚举 / span 口径**冻结**。

## 7. 明确禁止

1. `git push -f`（强推覆盖他人提交）；
2. 提交 `.env`、密钥、cookie、登录态、`storage_state.json`；
3. 提交 `__pycache__/`、虚拟环境、`.dsh-office-*`、`*.tmp`；
4. 提交单文件 > 50MB（数据用 manifest + 脚本重取）；
5. 直接改别人目录（先群里说，由负责人改）；
6. 全量提交 `data/raw/html/*.html`（`.gitignore` 已忽略，用 `manifest.csv` 记 SHA256）。

## 8. 常见坑速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `push` 被拒 | 云端有你没有的提交 | `git pull` 解冲突后再 push |
| `fatal: not a git repository` | 不在仓库目录 | `cd` 到 `团队仓库` |
| 提交显示成别人 | 没配 `user.name/email` | 重配，之后的新提交才生效 |
| 中文文件名显示乱码 | Git 转义 | `git -c core.quotepath=false status` |
| Excel 打开 CSV 乱码 | 编码不对 | 数据集统一 UTF-8-SIG |
| `git add .` 带进垃圾 | 图省事 | `git reset` 后改用 `git add 具体路径` |
| 大文件推不上去 | >100MB | `git rm --cached` 并加进 `.gitignore` |
| 改完发现改错分支 | 忘了切分支 | `git stash` → 切分支 → `git stash pop` |
