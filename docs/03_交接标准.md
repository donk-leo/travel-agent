# 03 · 交接标准（七项目契约）

> 这份文件回答一个问题：**项目 N 做完，交给项目 N+1 的到底是什么、什么条件才算交完。**
> 机器可读版本在 `standards/handover/pNN_*.yaml`，两者必须一致；冲突时以 YAML 为准并更新本文件。

---

## 1. 分工矩阵（谁交什么）

| 项目 | 主责（owner） | 复核（reviewer） | 产出位置 |
|---|---|---|---|
| P1 数据采集与预处理 | 三人各自负责一景区 | 交叉复核 | `scenic/<area>/` |
| P2 实体识别 | T0coke | HappinessJo | `analysis/p02_entities/` |
| P3 路线层级结构 | HappinessJo | T0coke | `analysis/p03_routes/` |
| P4 共指消解 | 成员3 | T0coke | `analysis/p04_coref/` |
| P5 条件建议抽取 | T0coke | 成员3 | `analysis/p05_conditions/` |
| P6 知识图谱 | T0coke | HappinessJo | `analysis/p06_graph/` |
| P7 旅游规划 Agent | HappinessJo | T0coke | `analysis/p07_agent/` |
| 总结反思 | 三人各写 1 条失败现象，组长汇总 | — | `report/章节/` |

**规则**：一个项目只有一个 owner；owner 不能兼自己的 reviewer；跨项目依赖只认 tag，不认“口头说好了”。

---

## 2. 什么算“交付完成”（五条必须同时成立）

1. **产出齐全**：文件名、路径与 `standards/handover/pNN_*.yaml` 完全一致；
2. **质量门通过**：`checks/check_pNN_*.py` 退出码 **0**（不是“我看着没问题”）；
3. **报告就位**：章节稿在 `analysis/pNN_*/report/`，含方法、参数、结果、问题；
4. **可复现**：他人 clone 后按 README 一条命令跑出同样结果（含固定随机种子）；
5. **交接卡更新**：`handover.yaml` 的 `status: done`、`version_tag` 已填、`reviewer` 已复核。

> 缺任一条 = 未交付。未交付的项目不允许被下游引用。

---

## 3. 交接卡（`standards/handover/pNN_*.yaml`）模板

```yaml
project: p02_entities
title: 游览步骤的实体识别
owner: T0coke
reviewer: HappinessJo
status: in_progress            # planned | in_progress | review | done | blocked
version_tag: ""                # done 时填 v0.2-p02

inputs:                        # 只读；必须来自上游产出
  - path: scenic/changlong/data/processed/changlong_guides.csv
    column: clean_content
    from_tag: v0.1-p01
outputs:                       # 文件名写死，下游按此读取
  - path: analysis/p02_entities/outputs/entities.jsonl
    schema: standards/schema_entities.json
  - path: analysis/p02_entities/outputs/entity_type_spec.md
checks:
  - python checks/check_entities.py analysis/p02_entities/outputs/entities.jsonl
frozen:
  - 实体类型枚举 POI / TRANSPORT / TIME
  - span 口径：基于 clean_content，0 起，不含结尾
acceptance:                    # 人工验收条件
  - 三景区各 POI ≥ 50 个、时间实体 ≥ 20 个
  - 人工抽查 20 条，误识别率 < 15%，记录在 report/
  - reviewer 复核通过并写备注
```

**`status` 语义**

| 值 | 含义 | 下游能否引用 |
|---|---|---|
| `planned` | 未开始 | ❌ |
| `in_progress` | 进行中 | ❌ |
| `review` | 产出齐全，等复核 | 仅本组内部试跑 |
| `done` | 已打 tag，可依赖 | ✅ |
| `blocked` | 卡住（写 `notes` 说明） | ❌ |

## 4. P1 数据采集与预处理

- **输入**：公开网页（官网 / 游记平台）
- **产出**
  - `scenic/<area>/data/processed/<area>_guides.csv`（24 列，UTF-8-SIG）
  - `scenic/<area>/outputs/质量检查报告.md`、`清洗前后对比.md`
  - `scenic/<area>/report/*.docx`（实验报告章节）
- **自检**：`python checks/check_scenic.py <该 csv>`
- **冻结**：`doc_id`、`clean_content`
- **验收**
  - [ ] 官方路线 ≥ 1 条（**必须是路线页**，不是须知/门票页）
  - [ ] 有效游客游记 ≥ 3 篇（建议 5）
  - [ ] 24 列齐全，`clean_hash` 无重复
  - [ ] 三景区数据可被 `merge_group.py` 合并
- **报告要点**：来源说明、清洗规则与前后对比、质量统计、问题与分析

---

## 5. P2 实体识别

- **输入**：三份 `*_guides.csv` 的 `clean_content`
- **产出**
  - `outputs/entities.jsonl`（字段见 `standards/schema_entities.json`）
  - `outputs/entity_type_spec.md`（定义/边界/示例/易混说明）
  - `outputs/figures/wordfreq_*.png`（词云或柱状图）
  - `outputs/stopwords_iteration.md`（停用词调整前后对比）
- **自检**：`python checks/check_entities.py analysis/p02_entities/outputs/entities.jsonl`
- **冻结**：实体类型枚举、span 口径
- **验收**
  - [ ] 三景区批量处理，单景区失败可重试且不中断全批
  - [ ] 每个实体含 `doc_id` + `char_start` + `char_end` + `char_start/end` 可回原文校验
  - [ ] 人工抽查 20 条记录误识别/漏识别，误识别率 < 15%
  - [ ] 词频图能看出噪声词，且给出停用词迭代前后差异

---

## 6. P3 路线层级结构

- **输入**：三份 `clean_content`（重点 2 个景区的官方路线）
- **产出**
  - `outputs/routes.jsonl`（步骤序列，字段见 `schema_routes.json`）
  - `outputs/hierarchy.json`（上午/中午/下午层级）
  - `outputs/route_structure.png`（结构图）
  - `outputs/compare_official_vs_user.csv`（附加题：两维度以上对比）
- **自检**：`python checks/check_routes.py analysis/p03_routes/outputs/routes.jsonl`
- **冻结**：步骤编号规则、时间层级口径
- **验收**
  - [ ] 至少 1–2 种格式可解析（箭头链路 / 编号列表 / 时间分段）
  - [ ] 未标注时间不得写成原文事实（要标 `time_source: absent/inferred`）
  - [ ] 名称归一化有规则表与局限说明
  - [ ] 对比分析给出原因，不是只有数字

---

## 7. P4 共指消解

- **输入**：三份 `clean_content`（优先游记）
- **产出**
  - `outputs/coref.jsonl`（代词 → 先行词，字段见 `schema_coref`）
  - `outputs/annotations.csv`（≥5 条人工标注，含 doc_id、句子、代词位置、真实先行词）
  - `outputs/eval.md`（准确率/覆盖率计算过程）
- **自检**：`python checks/check_coref.py analysis/p04_coref/outputs/coref.jsonl`
- **冻结**：标注字段定义、代词清单
- **验收**
  - [ ] 代词检测能给出位置，同句多个相同代词不串号
  - [ ] 标注含“无明确先行词”的处理规则
  - [ ] 至少一种消解方法 + 规则说明（POI 优先、距离/类型约束）
  - [ ] 评估指标可复算

---

## 8. P5 条件建议抽取

- **输入**：三份 `clean_content`（游记 + 官方）
- **产出**
  - `outputs/conditions.jsonl`（条件/建议/类型/来源/原句）
  - `outputs/映射表.xlsx`（条件类型、条件描述、建议内容、来源景区）
  - `outputs/figures/condition_stats.png`（按游客类型分组）
- **自检**：`python checks/check_conditions.py analysis/p05_conditions/outputs/conditions.jsonl`
- **冻结**：触发词表、条件类型枚举
- **验收**
  - [ ] 覆盖“如果/假如/若/建议/可以”等触发词
  - [ ] 条件与建议边界切分正确，多建议句有处理
  - [ ] 去重（同句/近重复/前后缀）有前后统计
  - [ ] 样本稀疏问题如实说明

---

## 9. P6 知识图谱

- **输入**：P2 `entities.jsonl` + P3 `routes.jsonl`（+ P5 `conditions.jsonl` 作为边属性）
- **产出**
  - `outputs/graph_nodes.csv` / `outputs/graph_edges.csv`（字段见 `schema_graph.json`）
  - `outputs/graph.graphml`（或 Neo4j 导入脚本）
  - `outputs/figures/graph_*.png`
  - `outputs/graph_qa.md`（查询验证、核心节点、缺失关系）
- **自检**：`python checks/check_graph.py analysis/p06_graph/outputs/`
- **冻结**：节点/边类型枚举、融合去重规则
- **验收**
  - [ ] 至少一个景区完整连通图（不是散点）
  - [ ] 节点/边类型在图例中可辨，关键路径可高亮
  - [ ] 给出融合规则：为什么合并、为什么保留
  - [ ] 有一条可执行的查询示例证明图可用

---

## 10. P7 旅游规划 Agent

- **输入**：P6 图谱（只读 `graph_nodes.csv` / `graph_edges.csv`）
- **产出**
  - `src/agent.py`、`src/tools.py`（图谱查询工具，Schema 见 `schema_tools.json`）
  - `outputs/sessions/*.jsonl`（思考-调用-观察轨迹）
  - `outputs/tests.md`（≥3 类场景：老人/亲子/情侣 · 一天/两天 · 不同景区）
  - `outputs/demo.md`（一条完整示范：约束解析 → 工具调用 → 行程生成）
  - `.env.example`（LLM 配置占位，密钥不入库）
- **自检**：`python checks/check_agent.py analysis/p07_agent/`
- **冻结**：工具 Schema、系统 Prompt
- **验收**
  - [ ] 回答基于图谱查询（轨迹里有 tool_call 与返回）
  - [ ] 无匹配/信息不足/冲突约束有回退或追问
  - [ ] 失败案例有分析（写进总结反思）

---

## 11. 总结反思（100 分）

- **产出**：`report/章节/总结反思.md`
- **要求**
  - 每人至少贡献 **1 个失败现象**（共 ≥2 个），按“操作 / 参数 / 数据 / 环境 / 系统误差”分层归因
  - 改进方案与失败问题**一一对应**，可落地、有变量控制思想
  - 局限性分五类：算法 / 数据 / 工程 / 泛化 / 评估（至少 2 条真实具体）
  - 只选 **1 个**突破点，给出研究路径 + 验证方式 + 预期新问题
- **自检**：无脚本；由 reviewer 对照任务书附表 1/2 逐条核对
